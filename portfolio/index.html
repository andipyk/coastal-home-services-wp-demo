Leads were copied into the CRM by hand.

A local home-services company (HVAC, plumbing, electrical) takes quote requests through its website. Each one gets retyped into a spreadsheet or CRM, and nothing records whether that follow-up happened. A lead can sit untouched for a day and nobody can tell.

What finished looks like, stated so it can be checked:

  • Every submission lands in WordPress as a structured record with phone, service type and status.
  • The record reaches the follow-up workflow with no copy and paste.
  • The workflow reports back, so the record itself shows it was synced and when.

Coastal Home Services is invented. I wrote this brief for myself and built the whole stack against it on my own time.

Every lead ends synced, or the audit log records that it did not.

Automation

A Make.com scenario that recovers from its own failures

Five modules in one scenario. A failed callback is caught by a Resume handler, every run is written to an audit log, and only runs whose callback succeeded are exported to the spreadsheet.

Data model

Lead post type and fields, in code

register_post_type() and acf_add_local_field_group() in a plugin, so the schema is versioned with everything else and survives a theme change.

Outbound

Form submit to webhook

A named function creates the lead and posts a JSON payload with wp_remote_post(). It runs from wp eval, so it can be tested without a browser.

Inbound

A signed REST callback

POST /wp-json/coastal/v1/lead-status checks a shared secret with hash_equals(). A wrong secret gets 403; the right one marks the lead synced.

Front end

Landing page built in Elementor

The quote form sits in an Elementor layout seeded from a script through Document::save(), so a fresh install rebuilds the same page.

What happens after someone presses submit.

Every name in the diagram and the steps is copied from the code or from the Make scenario.

  1. CaptureWPForms fires wpforms_process_complete. The plugin creates a lead post with status new and fills the ACF fields.
  2. Hand offwp_remote_post() sends the lead id, name, phone, service and a callback URL to the Make webhook. If that request fails it is logged, and the visitor's form still succeeds.
  3. Call backMake's HTTP module posts the lead id to the REST route with the shared secret. WordPress sets status synced and stamps synced_at.
  4. RecoverIf the callback fails, a Resume handler substitutes statusCode: 0, so the run completes and the next modules can tell a recovered failure from a response.
  5. RecordEvery run is written to a Data Store audit log. A filter lets a run through to Google Sheets only when statusCode is not 0.

wp-content/plugins/coastal-core/includes/rest.php: the inbound callback

// shared-secret auth: timing-safe, no cookie or nonce (the caller is not a browser)
'permission_callback' => function (WP_REST_Request $req) {
    return hash_equals(
        getenv('COASTAL_WEBHOOK_SECRET'),
        $req->get_header('x-webhook-secret') ?? ''
    );
},
